# Roadmap: CLI currency, sessions, multi-session, launch scoping

Date: 2026-11-10
Branch: `feat/cli-currency-and-sessions`

## Goal

Bring `@simpill/acp-llm-cli` up to date with the four CLIs it supports (Claude, Codex, Cursor,
Antigravity), then add durable sessions, multiple live sessions with switching, and scoped
launches (worktree, MCP servers, skills/agents/tools).

## Working rules

- All work lands on `feat/cli-currency-and-sessions`.
- Changes are grouped into logical commits. Nothing is committed until the owner has reviewed it.
- Each phase has its own spec and implementation plan, written when the phase starts.

## Phases

Each phase depends on the one before it.

| Phase | Delivers | Release |
|---|---|---|
| 1. Currency (done) | ACP SDK 2.x, all four providers on ACP with current commands, truthful flag tables, typed errors with install and login hints, generic options applied at spawn, `restart()` that restores the conversation | 0.5.0 (breaking) |
| 2. Foundations | Prompt cancel, per-request timeouts, a `doctor` check (installed, version, logged in, capabilities), permission presets, login flows driven through `authenticate` | 0.6.0 |
| 3. Session protocol | `listSessions`, `closeSession` on the port, gated by advertised capabilities; durable file store keyed by session id; transcript fallback | 0.7.0 |
| 4. Session manager | Several live sessions across providers, switching by session id, idle cap that stops the oldest idle process | 0.8.0 |
| 5. Launch scoping | One launch profile (worktree, extra directories, MCP servers, skills/agents/tools) translated per CLI into protocol fields or spawn flags | 0.9.0 |

Foundations comes before the session phases because the session manager needs all of it: it
cannot stop an idle session safely without cancel, cannot detect a hung agent without timeouts,
and cannot reopen a session on an agent that has been logged out without a login flow.

Phase 1 spec: [2026-11-10-phase-1-currency-design.md](./2026-11-10-phase-1-currency-design.md).

## Measured state (2026-11-10)

Capabilities each agent returned to a live ACP `initialize` on the development machine. The
current record is `docs/capabilities.md`.

| Agent | load | list | resume | close | delete | fork | extra dirs |
|---|---|---|---|---|---|---|---|
| Claude, `@agentclientprotocol/claude-agent-acp` | yes | yes | yes | yes | yes | yes | yes |
| Codex, `@agentclientprotocol/codex-acp` | yes | yes | yes | yes | yes | yes | yes |
| Cursor, `cursor-agent acp` | yes | yes | no | no | no | no | no |
| Antigravity 1.5.5, `agy acp` | yes | yes | yes | yes | no | no | yes |

Consequences carried into later phases:

- Every agent supports `session/load`; Cursor supports nothing else. The session layer must
  branch on advertised capabilities, never on provider id.
- On Cursor, closing a session means stopping its process.
- `session/load` replays history as `session/update` notifications. `restart()` already drops
  that replay; phase 3 must do the same for any other caller that should not render it twice.
- Agents report an unknown session differently: Claude with "not found", Cursor with "invalid
  params", Codex and Antigravity with a generic internal error. A failed restore cannot be told
  apart from a transient failure on those two, which is why phase 3 keeps a transcript so the
  conversation can be re-seeded into a new session.
- A session saved by one agent version may fail to load after the agent updates. Same remedy.
- Each live session on Cursor costs one process. Phase 4 caps the number kept alive.

## Later-phase sketches

These are intent, not design. Each is specified in full when its phase starts.

**Phase 2.** `cancel(sessionId)` on the port (`session/cancel`), with the pending prompt
settling as cancelled. A timeout option per request kind that rejects with `TimeoutError` and
leaves the link usable. `doctor(providerId)` returning installed, version, logged in and
advertised capabilities, built on the existing capability probe and `PROVIDER_SETUP`. Named
permission presets (ask, allow reads, allow all) over the existing permission handler. A login
helper that runs the agent's advertised auth method and reports what the user must do.

**Phase 3.** Add the remaining optional port methods mirroring the stable ACP session methods.
Replace the one-record-per-provider store with a store keyed by session id that also records
provider, cwd, title, timestamps and the agent version that created it. Ship a file-backed
implementation alongside the in-memory one. Add the transcript re-seed as the last restore
step after resume and load.

**Phase 4.** A session manager that owns a set of ports, routes prompts by session id, emits
which session is active, and enforces a configurable cap on live processes by stopping the
least recently used idle one. A stopped session is reopened on demand through phase 3.

**Phase 5.** A single launch profile type. Per provider, each field maps to an ACP field (`cwd`,
`mcpServers`, `additionalDirectories`), to a spawn flag from the phase 1 flag tables, or is
reported as unsupported. Worktree creation is done by this package with `git worktree` where the
CLI has no native option, so behaviour is the same across providers.
