# Roadmap: CLI currency, sessions, multi-session, launch scoping

Date: 2026-11-10
Branch: `feat/cli-currency-and-sessions`

## Goal

Bring `@simpill/acp-llm-cli` up to date with the four CLIs it supports (Claude, Codex, Cursor,
Gemini), then add durable sessions, multiple live sessions with switching, and scoped launches
(worktree, MCP servers, skills/agents/tools).

## Working rules

- All work lands on `feat/cli-currency-and-sessions`.
- Changes are grouped into logical commits. Nothing is committed until the owner has reviewed it.
- Each phase has its own spec and implementation plan, written when the phase starts.

## Phases

Each phase depends on the one before it.

| Phase | Delivers | Release |
|---|---|---|
| 1. Currency | ACP SDK 2.x, all four providers on ACP with current commands, truthful flag tables, cleanup | 0.5.0 (breaking) |
| 2. Session protocol | `loadSession`, `resumeSession`, `listSessions`, `closeSession` on the port, gated by advertised capabilities; replay suppression on load; durable file store keyed by session id; transcript fallback | 0.6.0 |
| 3. Session manager | Several live sessions across providers, switching by session id, idle cap that stops the oldest idle process | 0.7.0 |
| 4. Launch scoping | One launch profile (worktree, extra directories, MCP servers, skills/agents/tools) translated per CLI into protocol fields or spawn flags | 0.8.0 |

Phase 1 spec: [2026-11-10-phase-1-currency-design.md](./2026-11-10-phase-1-currency-design.md).

## Measured starting point (2026-11-10)

Capabilities each agent returned to a live ACP `initialize` on the development machine:

| Agent | load | list | resume | close | delete | fork | extra dirs |
|---|---|---|---|---|---|---|---|
| Claude, `@agentclientprotocol/claude-agent-acp` 0.106.0 | yes | yes | yes | yes | yes | yes | yes |
| Cursor, `cursor-agent acp` 2026.11.05 | yes | yes | no | no | no | no | no |
| Gemini 0.33.2, `gemini --acp` | yes | no | no | no | no | no | no |
| Codex, `@agentclientprotocol/codex-acp` 2.6.0 | not measured: no reply within 25s through `npx` | | | | | | |

Consequences carried into later phases:

- Every measured agent supports `session/load`; only Claude supports the rest. The session layer
  must branch on advertised capabilities, never on provider id.
- On Cursor and Gemini, closing a session means stopping its process.
- `session/load` replays history as `session/update` notifications. Phase 2 must mark or drop the
  replay so consumers do not render it twice.
- A session saved by one agent version may fail to load after the agent updates. Phase 2 keeps a
  transcript so the conversation can be re-seeded into a new session.
- Each live session on Cursor and Gemini costs one process. Phase 3 caps the number kept alive.

## Later-phase sketches

These are intent, not design. Each is specified in full when its phase starts.

**Phase 2.** Add optional port methods mirroring the stable ACP v1 session methods. Replace the
one-record-per-provider store with a store keyed by session id that also records provider, cwd,
title, timestamps and the agent version that created it. Ship a file-backed implementation
alongside the in-memory one. Replace the restart path, which today calls `newSession` with a
`sessionId` cast onto the request, with `session/resume` where advertised, else `session/load`,
else transcript re-seed.

**Phase 3.** A session manager that owns a set of ports, routes prompts by session id, emits
which session is active, and enforces a configurable cap on live processes by stopping the
least recently used idle one. A stopped session is reopened on demand through phase 2.

**Phase 4.** A single launch profile type. Per provider, each field maps to an ACP field (`cwd`,
`mcpServers`, `additionalDirectories`), to a spawn flag from the phase 1 flag tables, or is
reported as unsupported. Worktree creation is done by this package with `git worktree` where the
CLI has no native option, so behaviour is the same across providers.
